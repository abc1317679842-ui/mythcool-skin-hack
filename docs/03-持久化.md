# 03 · 持久化：让补丁活过重启

补丁全在内存里，Myth.Cool 一重启就没了。这一层负责**自动打回去**。

## 设计目标

| 目标 | 怎么做到 |
|---|---|
| 覆盖所有重启场景 | 登录触发 + **每 1 分钟轮询**（一条触发管三种场景） |
| 平时零打扰 | **幂等**：`PID 没变` **且** `inject_main.py 的哈希没变` 才跳过，不启动 Python |
| 不闪窗口 | 走 `wscript.exe`（GUI 子系统）+ 隐藏启动 |
| 失败可恢复 | **只有注入成功才记账**，失败留待下一轮自动重试 |
| 改了代码就生效 | 幂等键里带**注入器自身哈希**（v22）—— 否则「换了 inject_main.py 但 PID 没变」会永远不重注入 |
| 换皮肤不掉 | **主进程自愈守卫**（v22）：页面被切皮肤重建后，10 秒内自动补打 |

## 组件

```
InjectSilent.vbs      ← 计划任务的【真正入口】（无窗口启动器）
   │
   ├─ MythCool 没在跑 且 state=NONE → 直接退出（~120ms，PowerShell 一次都不启动）
   │
   └─ 其它任何情况 → 一律降级 ↓（★ 这里【故意】不做 PID 比对，原因见下）
Inject.ps1            ← 完整逻辑：找主进程 + 比注入器哈希 + 调注入器 + 记账
   │
   └─ <本机 Python> inject_main.py <pid>
        运行时按顺序探测：venv\Scripts\python.exe → python\python.exe
                        → python\Scripts\python.exe → PATH 上的 python.exe
```

> ⚠️ **Python 路径必须运行时探测，不能写死。**
> `Setup-Runtime.ps1` 能建 venv 时会生成 `venv\Scripts\python.exe`，
> 但在**没有基础 Python 的机器**上它会退回到嵌入式运行时 `python\python.exe`。
> 写死任何一个，在另一种装机布局上就会变成 `FATAL missing python` + exit 3，**注入彻底死掉**。

计划任务：

| 项 | 值 |
|---|---|
| 名称 | `MythCoolInject`（老版本安装包可能注册成 `MythCoolSkinHack`） |
| 触发器 | `AtLogOn` + `Once/每 1 分钟重复（无限）` |
| 动作 | `wscript.exe //B //NoLogo "...\InjectSilent.vbs"` |
| 身份 | 当前用户 / `Interactive` / **`HighestAvailable`** |
| 设置 | `IgnoreNew` + `StartWhenAvailable` + 5 分钟上限 |

## 三个关键设计

### ① 幂等：怎么知道"已经打过了"

两个 state 文件：

| 文件 | 内容 |
|---|---|
| `state\last_pid.txt` | 上一次**成功注入**的 PID（或 `NONE`） |
| `state\last_hash.txt` | 上一次成功注入时 `inject_main.py` 的 **sha256**（v22 新增） |

```
PID 没变 且 哈希没变  →  秒退（确实已经打过了）
PID 变了 或 哈希变了  →  注入 → 成功才写两个文件
                        失败不写 → 下一轮自动重试
MythCool 没在跑       →  写 "NONE"
```

**「失败不记账」是这套东西最容易忽略、但最重要的一条** ——
如果失败也记账，就会出现「以为成功了，其实副屏一直是原样」的静默故障。

**为什么幂等键里必须带哈希（v22 的教训）**：
PID 只反映「官方软件有没有重启」。**替换 `inject_main.py` 不会改 PID** ——
于是「PID 没变就跳过」会把**每一次注入器更新**都静默吞掉：计划任务每分钟照跑、
返回码 0、日志一行不加，而新代码永远进不了页面。
⇒ 加了 `inject_main.py` 的 sha256 之后，**改完代码部署完，下一分钟自动重注入一次**，不用 `-Force`。

> ⚠️ **判据绝不能用 mtime**：`Copy-Item` 会把**源文件的时间戳**带给目标，
> 于是「目标比上次新」这个判断会说谎（历史上就栽在 mtime 上）。哈希不会。
>
> ⚠️ **`InjectSilent.vbs` 里那个 PID 快速跳过已经删掉了**（v22）。
> 它原本是「省钱」优化，但它是**计划任务的真正入口** —— 它一跳过，`Inject.ps1` 连启动的机会都没有，
> 上面那个哈希判据**根本没机会执行**。现在 VBS 只保留「Myth.Cool 没在跑且 state=NONE」这一种跳过，
> 因为那种情况不可能藏住任何工作。代价是每分钟多花 ~370 ms 启动 PowerShell，**换来正确性**。

### ② 怎么找到"真正的"主进程

MythCool.exe 有 **5 个进程**，而且**启动时间完全相同**：

```
pid=26308 ppid=22692  ← 主进程（父进程不是 MythCool.exe）
pid=16708 ppid=26308  ← --type=gpu-process
pid=27868 ppid=26308
pid=11992 ppid=26308
pid=23164 ppid=26308
```

所以「按启动时间排序取第一个」**选不准**。可靠判据是**父子关系**：

```powershell
$ids  = @($raw | ForEach-Object { $_.ProcessId })
$cand = @($raw | Where-Object { $ids -notcontains $_.ParentProcessId })
```

主进程是**唯一一个"父进程不是 MythCool.exe"的**。

> 为什么不用 `CommandLine` 里的 `--type=` 过滤？因为**非提权时读不到高完整性进程的
> CommandLine**（返回 access denied），过滤会全部失效。

### ③ 怎么做到不闪窗口

**`powershell.exe -WindowStyle Hidden` 是治不了闪窗的** —— Windows 在**进程创建时**
就给控制台程序分配了窗口，而 `-WindowStyle` 是 PowerShell 启动**之后**才执行的。

正确做法：用 **`wscript.exe`**（GUI 子系统，**根本没有控制台**）去启动，
再用 VBS 的 `Run(cmd, 0, True)` 把子进程隐藏：

```vbs
rc = sh.Run("powershell.exe ... -File ""...\Inject.ps1""", 0, True)
'                                                            ↑  ↑
'                                            0=隐藏窗口       等待它跑完
```

`True`（等待）很重要：任务会一直处于 "Running" 状态，
`MultipleInstances=IgnoreNew` 和 `ExecutionTimeLimit` 才有意义。

### ④ 页面重建后的自愈（v22）

**病**：切换皮肤（尤其切到自定义皮肤）会**销毁并重建 mainpage 渲染进程** ——
页面里注入的一切（`<style>`、浮层、定时器、观察者、换肤探测）**全部蒸发**。
而上面那套幂等只管「官方软件重启」，页面重建**不改 PID** ⇒ 页面一重建就**永远不再注入**。
用户看到的现象是：「第一次切回来有效，多切几次之后就再也不注入了」。

**修**：把守卫放在**主进程**（它活得过页面重建），三层：

| 层 | 做法 | 成本 |
|---|---|---|
| 事件（主） | `app.on('web-contents-created')` → `did-finish-load` → 1.2 s 后查 `typeof window.__mtc_apply` | 零轮询 |
| 轮询（兜底） | 每 **10 s** 查同一个表达式；事件拿不到时靠它 | 每 10 s 一次 `executeJavaScript`，可忽略 |
| 补配置 | 重打 PATCH 后**立刻补推一次 `tune.json`** | —— |

判定「页面是不是新的」就一句话：`typeof window.__mtc_apply === 'function'` 说明代码还在；`'undefined'` 说明页面被重建过。

**怎么区分这两类「没生效」**（排查时先看这个）：

| 现象 | 含义 |
|---|---|
| `inject.log` 每次注入都写新行 | 注入链路正常 |
| 日志**一行都不加**，但任务 `LastResult=0` | 被幂等跳过了（PID + 哈希都没变，属正常）；**但如果刚改过代码，就是 v22 之前那个坑** |
| 日志正常、页面里却 `__mtc_apply === 'undefined'` | 页面被重建过，等主进程守卫补打（≤10 s） |

> ⚠️ 查日志前先看 `Get-ScheduledTaskInfo -TaskName MythCoolInject` 的 `LastRunTime` ——
> 任务每分钟才跑一次，你读日志的那一刻上一轮可能还没发生（实测误判过一次）。

## 性能：为什么保留 VBS 这一层

实测每次调 PowerShell 的成本：

| 项 | 耗时 |
|---|---|
| `Inject.ps1` 秒退路径总计 | **530 ms** |
| 其中：空 `powershell.exe` 启动+退出 | **373 ms** |
| VBS 单独跑完「查 PID + 读 state」（不启动 PowerShell） | **~120 ms** |

VBS 这一层**保留**，目的有两个，都不是为了省钱：

1. **不闪窗口**（见上）—— 这是 `wscript.exe` 的硬性优势，`-WindowStyle Hidden` 治不了；
2. **官方软件没开时秒退** —— `PID 空 且 state=NONE` 直接退出，不开 PowerShell。

**代价**：官方软件开着时，每分钟要多花 ~370 ms 启动 PowerShell（约 0.09% 单核，可忽略），
换的是**改代码必生效**。这笔账在 v22 明确划到「正确性优先」这边。

## 为什么不做「事件触发」

Windows **没有**「某个进程启动了」这种原生事件源。看起来可行的三条路都更差：

| 方案 | 问题 |
|---|---|
| Security 日志 **4688**（进程创建审核） | 默认关闭；开启要改本地安全策略；**记录全系统每一次进程创建** ⇒ 开销比现在大几个数量级 |
| **Sysmon** EventID 1 | 要额外装驱动级工具 |
| **WMI 永久事件订阅**（`__InstanceCreationEvent` + `CommandLineEventConsumer`） | **底层仍是轮询**（`WITHIN` 最小 1 秒粒度），监控范围是全系统进程创建 ⇒ 比现在贵得多；还会在系统里留一个**持久自动执行点**（安全软件很敏感） |

**而且现有机制已经覆盖了全部场景**：

- **开机/登录** → `AtLogOn` 触发器
- **睡醒** → 计时器在休眠期间暂停，唤醒后 `StartWhenAvailable=True` 会**立即补跑一次**；
  等自愈脚本把 Myth.Cool 重启完，下一轮（≤1 分钟）自动补上
- **手动重启** → 轮询兜底

## 手动控制（PowerShell 终端，管理员）

```powershell
# 看它现在会做什么（只读，不注入、不写日志）
& 'C:\ProgramData\MythCoolInject\Inject.ps1' -Probe

# 强制重新注入一次
& 'C:\ProgramData\MythCoolInject\Inject.ps1' -Force

# 删除任务（先查实际名称；老安装包可能注册成 MythCoolSkinHack）
Get-ScheduledTask -TaskName 'MythCool*' | Format-Table TaskName, State
Unregister-ScheduledTask -TaskName 'MythCoolInject' -Confirm:$false
```

> 注意是 **PowerShell 原生命令**，不是 cmd 的 `del` / `copy /Y` / `&` 混用 ——
> PS 5.1 里 `&` 是调用运算符，`&&` 直接是语法错。要给 cmd 命令就写成单行 `cmd /c "…"`。

## 相关文件

| 文件 | 作用 |
|---|---|
| `state\last_pid.txt` | 幂等键①：上次成功注入的 PID |
| `state\last_hash.txt` | 幂等键②：上次成功注入时 `inject_main.py` 的 sha256（v22） |
| `log\inject.log` | 注入时间线（`[PS]` / `[py]` 两种前缀） |
| `log\tune_ack.txt` | 每次推配置的确认 |
| `log\last_result.json` | 注入时的页面快照（含**皮肤识别结果** `skin` / `skinCfg`） |

> ⚠️ 非提权终端跑 `Inject.ps1` 时，`Add-Content` 写 `log\inject.log` 会被拒绝，
> 而 `Log()` 有 try/catch ⇒ **静默无痕**。排查「任务跑了但没日志」时要想到这一层。
