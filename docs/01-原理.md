# 01 · 原理

> 为什么必须用运行时注入？注入是怎么做到的？为什么注入完 frida 就能退出？

## 1. 为什么不能直接改文件

Myth.Cool 的皮肤打包在 `webapp.gpk` 里。`gpk` 是 asar 式归档（可以用
`fs.readFileSync('xxx.gpk/windows/pages/mainpage.html')` 当目录读），
**但它带完整性校验** —— 改动任意一个字节，整个皮肤会被判定为损坏。

所以「改皮肤文件」这条路是死的。剩下的路只有两条：

| 路线 | 做法 | 代价 |
|---|---|---|
| **A. 替代** | 自己写程序直接驱动 USB 屏，绕开 Myth.Cool | 要换 USB 驱动、必须关掉官方软件、官方皮肤全废 |
| **B. 注入**（本项目） | 在 Myth.Cool 运行时改它的内存 | 需要附加到进程、跟随官方软件版本 |

选 B 的理由见 [README 对比表](../README.md#和其他开源方案的区别-)。

## 2. Myth.Cool 的技术栈

它是个 **Electron 应用**：

```
MythCool.exe                     ← 主进程（Node.js + Electron）
├── --type=gpu-process           ← 子进程
├── --type=renderer              ← 子进程（皮肤页面跑在这里）
├── 还有若干个 gpu / utility 子进程
```

主进程有一个关键能力：`BrowserWindow.getAllWindows()` → 拿到窗口 →
`webContents.executeJavaScript(code)` → **把任意 JS 送进渲染进程执行**。

这正是我们需要的：**只要能往主进程里送一段代码，就能让它帮我们把补丁送进皮肤页面。**

## 3. 怎么往主进程里送代码

frida 可以 attach 到 Electron 主进程，但**不能直接跑 JS** —— Electron 的 Node 上下文
不等于 frida 的 JS 运行时。所以要走 **V8 的 C++ API**：

```js
// 1. 拿到当前 isolate（V8 的实例）
Isolate::GetCurrent()
// 2. 拿到当前 context
Isolate::GetCurrentContext()
// 3. 建一个 HandleScope（V8 要求）
HandleScope::HandleScope(iso)
// 4. 把 JS 源码变成一个 V8 String
String::NewFromUtf8(iso, source)
// 5. 编译成 Script
Script::Compile(ctx, src)
// 6. 跑它！
Script::Run(ctx)
```

这六个符号都是 **C++ 修饰名**（mangled name），因为 V8 是 C++ 写的：

```js
var Syms = {
  GetCurrent:          '?GetCurrent@Isolate@v8@@SAPAV12@XZ',
  GetCurrentContext:   '?GetCurrentContext@Isolate@v8@@QAE?AV?$Local@VContext@v8@@@2@XZ',
  NewFromUtf8:         '?NewFromUtf8@String@v8@@SA?AV?$MaybeLocal@VString@v8@@@2@PAVIsolate@2@PBDW4NewStringType@2@H@Z',
  Compile:             '?Compile@Script@v8@@SA?AV?$MaybeLocal@VScript@v8@@@2@V?$Local@VContext@v8@@@2@V?$Local@VString@v8@@@2@PAVScriptOrigin@2@@Z',
  Run:                 '?Run@Script@v8@@QAE?AV?$MaybeLocal@VValue@v8@@@2@V?$Local@VContext@v8@@@2@@Z',
  HsCtor:              '??0HandleScope@v8@@QAE@PAVIsolate@1@@Z'
};
for (var k in Syms) A[k] = Module.getGlobalExportByName(Syms[k]);
```

> ⚠️ **这些符号名是版本相关的**。换 Electron 大版本后如果注入失败，
> 第一步就是重新 dump 这些符号（可以用 `Module.enumerateExports()` 找 `Isolate`/`Script` 相关的导出）。

## 4. 什么时候注入

**Electron 主进程启动早期，V8 还没有当前 Context** —— 这时候调 `GetCurrentContext()` 拿到的是空指针。

解决办法：**hook libuv 的事件循环入口**，等主进程跑起来再动手：

```js
function hookIt(name) {
  var addr = Module.getGlobalExportByName(name);
  Interceptor.attach(addr, {
    onEnter: function () {
      if (done) return;
      try { if (inject()) done = true; } catch (e) {}
    }
  });
}
hookIt('uv_timer_start');
hookIt('uv_async_send');
```

这两个函数在 Node 的主循环里被高频调用，**第一次调用时 Context 一定已经就绪了**。

## 5. 补丁怎么进渲染进程

注入进主进程的这段代码（`inject_main.py` 里的 `MAIN`）做三件事：

```js
// ① 等 mainpage 窗口出现（软件刚启动时窗口可能还没建）
function loop() {
  var w = findW();                       // 遍历 BrowserWindow 找 mainpage.html
  if (!w) { setTimeout(loop, 2000); return; }   // 每 2 秒重试，最多 120 秒
  W = w;
  // ② 把补丁送进渲染进程
  w.webContents.executeJavaScript(PATCHCODE).then(...);
}
// ③ 挂上 tune.json 的热调监听
fs.watchFile(TUNEPATH, { interval: 1200 }, function () {
  W.webContents.executeJavaScript('window.__MTC_TUNE=' + t + ';(window.__mtc_apply||function(){})()');
});
```

`PATCHCODE` 就是那一段在皮肤页面里跑的 JS（追加 `<style>`、建 DOM 节点、起 3 秒节拍）。

## 6. ★ 为什么注入完可以立刻退出

这是本项目的一个关键设计 —— **frida 只在"送代码"这一刻是必需的**：

| 东西 | 跑在哪 | 依赖 frida 吗 |
|---|---|---|
| 追加的 `<style>` 标签 | 渲染进程 DOM | ❌ 不依赖 |
| 自建的 DOM 节点 | 渲染进程 DOM | ❌ 不依赖 |
| 3 秒刷新 `setInterval` | 渲染进程 JS | ❌ 不依赖 |
| `tune.json` 热调 `fs.watchFile` | 主进程 Node | ❌ 不依赖 |

所以 `inject_main.py` 注入完就 `session.detach()` 退出了 —— **补丁继续活着**。
这意味着：不需要常驻守护进程，不需要 frida 一直挂着，没有任何额外开销。

> 唯一的代价：注入的东西活不过 Myth.Cool 重启（全在内存里）。
> 所以才有 [持久化方案](03-持久化.md)。

## 7. 补丁长什么样

`PATCH` 里做的事情，按重要性排：

```js
// ① 排版：追加一个 <style>，塞进任何你想塞的 CSS
function instCSS() {
  var s = document.createElement('style');
  s.id = '__mtc_v13css';
  document.head.appendChild(s);
  s.textContent = [...内置规则..., String(CFG.css || '')].join('');
  //                ^^^^^^^^^^^^             ^^^^^^^^^^^^^^^^^
  //                主排改造                  tune.json 里的任意 CSS
}

// ② 新数据项：从皮肤已有的 localStorage 数据里取，建成绝对定位的 div
function build() {
  var v = vals();      // 从 localStorage['bg_sensor_data'] 里读传感器
  for (var it of ITEMS) {
    var el = document.querySelector('[data-mtc="' + it.id + '"]') || create();
    el.style.left = CFG.ix + 'px';
    el.style.top  = (CFG.tops[it.id]) + 'px';
    el.innerHTML = '<b>' + it.label + '</b><span class="mtc-val">' + v[it.key] + '</span>';
  }
}

// ③ 自带 3 秒节拍（关键：否则新数据项会冻住）
function startTick() {
  window.__mtc_v13timer = setInterval(function () { refresh('tick'); }, CFG.refresh_ms || 3000);
}
```

> **为什么必须有 ③**：原生皮肤自己的刷新是 3 秒一次（`SensorRefreshTime` 未设时
> 代码里 `: a=3e3` 兜底）。如果我们的新增项只依赖"值变化"触发，那**当内存/显存占用
> 长时间不变时，这几项会一直冻在旧值** —— 哪怕主板温度涨了 10 度。

**安全性**：`fixRows()` / `build()` 内部都有**值去重**（`if (txt !== zh)` / `if (el.innerHTML !== html)`），
值没变就不碰 DOM ⇒ 不会跟 Vue 的 patch 抢 DOM。

## 8. 数据从哪来

皮肤页面（渲染进程）能直接读 `localStorage['bg_sensor_data']`，这是 Myth.Cool
自己写的传感器数据（每秒更新）。里面有的字段：

```jsonc
{
  "cpu":       { "temp": 45, "voltage": 1.03, "power": 65, ... },
  "gpu":       { "temp": 52, "voltage": 0.81, "mem_temp": 58, "mem_usage_mb": "3200M/16384M", ... },
  "mainboard": { "temp": 38, "voltage": 12.1 },
  "memory":    { "temp": 41, "usage": 49.3 },
  "gpu_list":  [ ... ]
}
```

**这就是为什么新增数据项不需要额外装 HWiNFO 之类的工具** —— 官方软件已经采好了，
我们只是把它没显示出来的字段显示出来。

> 想加别的项？在皮肤页面 console 里 `JSON.parse(localStorage.bg_sensor_data)` 看一眼
> 有哪些字段，然后往 `ITEMS` 数组里加一条就行。
