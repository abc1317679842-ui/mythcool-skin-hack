# 04 · 踩坑合集 ★

> 这一篇是本项目最有价值的部分。下面每一条都是**真踩过、真浪费时间**的坑，
> 按「症状 → 原因 → 正确做法」写。改 Myth.Cool 皮肤（或做同类 Electron 注入）之前先读一遍，
> 能省几个小时。

---

## 1. `webapp.gpk` 有完整性校验，不能改文件

**症状**：改了皮肤文件，整个皮肤失效 / 软件报错。

**原因**：`gpk` 是带校验的 asar 式归档。

**正确做法**：只在**运行时改内存**。所有改动都在渲染进程的 DOM 和主进程的 JS 里，
软件重启就干净 —— 这也是本项目「完全可逆」的来源。

---

## 2. ★★ 类名会被多个组件复用 —— 用宽选择器会误伤一大片

**症状**：修好了 A 组件，B 组件却坏了（一个消失、一个位移）。

**原因**：Myth.Cool 的类名很多来自**配置数据**，不是写死的字面量：

```js
// mainpage.js 里不同组件用的是同一个 customClass
networkMonitoringVesselsData:  { num:1, unit:"MB/s", customClass:"AeeAndCui" }
CPUmonitoringVesselsData:      { num:1, unit:"℃",    customClass:"AeeAndCui img_back" }
GPUmonitoringVesselsData:      { num:1, unit:"W",     customClass:"AeeAndCui img_back" }
```

它们走同一个渲染分支 `1===e.num → div.hardware-infor.outside.[customClass]`，
所以 `.hardware-infor.outside.AeeAndCui{...}` 这一条规则**同时命中好几个组件**。

**后果实测**（用当时那条宽规则）：

| 规则 | 后果 |
|---|---|
| `:not(.triangle_icon2){left:auto;right:-11px}` | 把右侧 4 个标签从 `left:10px` 硬拽成右对齐 → **其中一个直接出界** |
| `width:auto;min-width:0` | 宽度从 `BoxWidth:134` 收缩 → 自带的 `background` 图片被裁 → **右边框整段消失** |

**正确做法**：

1. **改任何选择器之前，先在页面里确认它匹配几个元素**：
   `document.querySelectorAll('你的选择器').length`
2. **优先用「运行时内容特征」定位**，而不是类名：

```js
// 只认「块里的 span 文本是 MB/s」的那种块 —— 这才是网络块
var els = document.querySelectorAll('.hardware-infor.outside.AeeAndCui');
for (var i = 0; i < els.length; i++) {
  var sp = els[i].querySelector('span');
  if (String(sp.textContent || '').trim() !== 'MB/s') continue;   // ← 只碰网络块
  els[i].style.setProperty('clip-path', 'none', 'important');     // inline !important 必胜
}
```

3. 实在要用类名，就用**独有的那个类**做 `:not()` 排除，例如 `:not(.img_back)`。

## 3. ★★ `clip-path` 是隐形裁切源，`scrollWidth` 查不出来

**症状**：文字最右边总是被切掉一点（本例是 `MB/s` 末尾的 `s`）。
把元素的 `overflow`、`padding` 全查了一遍，**全都正常**。

**原因**：皮肤 CSS 里有这么一条：

```css
.hardware-infor[data-v-b5fe9c4a]{
  -webkit-clip-path: polygon(0 0, 9% 100%, 100% 100%, 91% 0);
  background: linear-gradient(90deg, #a196f3, rgba(161,150,243,0));
}
```

**那个 9% 斜角本来是切它自己的紫色渐变底的。** 但本皮肤把 `background` 改成了
`transparent` 却没撤斜角 —— 于是斜角只剩一个作用：**把最右 9% 的文字斜着削掉**。

而且**百分比随元素尺寸走**：数字越长块越宽 ⇒ 斜切区绝对量越大 ⇒ 削得越多
（用户的原话是「S 显示得越来越少」，当时还以为是"自适应在跳动"）。

**为什么之前找了两轮都没找到**：`clip-path` **完全不改变布局尺寸** ——
`scrollWidth == clientWidth` 恒成立，查 `overflow` 永远查不到它。

**正确做法**：判断「元素被裁」的完整清单是

```
overflow（含所有祖先）
  → clip-path / -webkit-clip-path     ← 最容易漏
  → mask / -webkit-mask
  → contain: paint
```

治本：`clip-path: none !important`。别指望调字号或 padding ——
padding 的百分比是相对包含块算的，治不了。

**另一个更可靠的判别手段**：用 `document.elementsFromPoint()` **沿元素长轴逐像素采样**，
看最后一个是哪个 px 还能命中原元素 —— 被裁掉的部分不参与命中测试，
所以能**精确量出可见末端**，不靠目测也不靠推算。

## 4. `scrollWidth == clientWidth` 证明不了「没被裁」

**症状**：拿到 `scrollW == clientW` 的数据，据此判定「没被裁」，结论错了。

**原因**：被检查的元素自己 `overflow: visible`，**它本来就不会裁自己**。
裁切可以发生在**任意祖先** —— 而当时的 dump 里只取了「往上第一个 position != static」
的祖先，**没有任何一层祖先的 overflow 被 dump**。

**正确做法**：dump **完整祖先链**，每一层都记 `overflow` / `clip-path` / 真实
padding-box 边界。本项目就是在补上祖先链之后一眼看到 `clip-path` 的
（当初只 dump `overflow` 的话，永远找不到）。

## 5. ★ Electron 子进程的启动时间完全相同 —— 不能按时间选主进程

**症状**：脚本 attach 上的进程里没有 `require`，注入全失败。

**原因**：MythCool.exe 有 5 个进程，**主进程和 4 个 helper 的启动时间一模一样**：

```
pid=26308 ppid=22692 created=05:37:02   ← 主进程
pid=16708 ppid=26308 created=05:37:02   ← --type=gpu-process
pid=27868 ppid=26308 created=05:37:02
pid=11992 ppid=26308 created=05:37:02
pid=23164 ppid=26308 created=05:37:09
```

`Get-Process | Sort-Object StartTime | Select -First 1` **选不准**。

更麻烦的是：非提权时 `frida.enumerate_processes()` **只暴露了那个 gpu-process**，
而按 `--type=` 过滤因为读不到 `CommandLine`（access denied）而失效 ——
于是 attach 到了 gpu-process，报 `ProcessNotRespondingError`。

> ⚠️ 这个报错**极易误判成权限问题**。我们当时就误判成「必须管理员才能 attach」，
> 实际是**选错了进程**；换成主进程后，非提权也能注入成功。

**正确做法**：用**父子关系**判据（`ParentProcessId` 不需要特权就能读）：

```powershell
$ids  = @($raw | ForEach-Object { $_.ProcessId })
$cand = @($raw | Where-Object { $ids -notcontains $_.ParentProcessId })
# 主进程 = 唯一一个「父进程不是 MythCool.exe」的
```

## 6. `-WindowStyle Hidden` 治不了闪窗

**症状**：计划任务每分钟跑一次，屏幕上**有个黑框一闪而过**。

**原因**：`powershell.exe` 是**控制台子系统**程序。Windows 在**进程创建的那一刻**
就给它分配了 conhost 窗口，而 `-WindowStyle Hidden` 是 PowerShell **启动之后**
才执行的 —— 中间那几百毫秒窗口就是可见的。

**正确做法**：用 **`wscript.exe`** 启动（GUI 子系统，**根本没有控制台**），
再用 VBS 的 `Run(cmd, 0, True)` 隐藏子进程：

```vbs
rc = sh.Run("powershell.exe -NoProfile ... -File ""...\Inject.ps1""", 0, True)
'                                                                  ↑  ↑
'                                                  0 = 隐藏窗口     等待完成
```

**为什么第二个参数必须是 `True`**：不等待的话任务会立即结束，
`MultipleInstances=IgnoreNew` 和 `ExecutionTimeLimit` 就都失效了。

## 7. `*> 文件` 重定向失败会中止整轮

**症状**：注入莫名其妙没执行，日志里只有一句「injector threw」。

**原因**：PowerShell 里 `& $exe ... *> $file` 如果**打不开目标文件**（被占用、无权限），
会产生 **terminating error** —— `try/catch` 也接不住重定向本身的失败，整轮直接中断。

**正确做法**：用管道，不要用文件重定向：

```powershell
& $PY $MAIN $cur 2>&1 | Out-Null      # 管道不打开文件句柄，失败也不会中断
```

（输出记录交给被调脚本自己写日志文件。）

## 8. 跨窗口的 `localStorage` 写入抓不到

**症状**：hooks 了 `Storage.prototype.setItem`，但一次都没触发，看起来像"数据没更新"。

**原因**：`bg_sensor_data` 是 **background 窗口**写的，
而你在 **mainpage 窗口**里 hook 的是**本窗口**的 `Storage.prototype` ——
**跨窗口写入永远抓不到**。

**正确做法**：用跨窗口事件：

```js
window.addEventListener('storage', function (e) {
  if (e.key === 'bg_sensor_data') { /* 这里才会触发 */ }
});
```

## 9. CSS 属性字符串匹配陷阱：`[style*="clip-path"]` 在 `clip-path: none` 时仍然匹配

**症状**：MutationObserver 的条件恒为假，观察器**从来没触发过**。

**原因**：本来想表达"如果还没有我们处理过的块"，写成了：

```js
!document.querySelector('.hardware-infor[style*="clip-path"]')
```

但处理完之后元素的行内样式是 `clip-path: none` —— **字符串里仍然含 "clip-path"**，
所以选择器**照样匹配** ⇒ `!matches` 恒为 `false` ⇒ 条件永远不成立。

**正确做法**：别用属性字符串匹配来表达"处理过了"，
改用**语义明确的检查**（比如"目标元素是否还在"），或者干脆打标记：
`el.setAttribute('data-patched', '1')` 然后查 `[data-patched]`。

## 10. Vue 组件重建后钩子失效 —— 守卫要**版本化**命名

**症状**：新版本脚本装上了，但 `$watch` 就是不生效。

**原因**：旧版本在 `vm` 上留了个 `vm.__mtc_hooked = true` 的标记，
新版本第一句是 `if (vm.__mtc_hooked) return true;` ⇒ **新版的钩子从来没注册进去**。

**正确做法**：每个版本用**自己的**守卫名：

```js
function hookUpdates() {
  var vm = findVmOnce('gpumemload');
  vm.__mtc_hooked = true;        // 占住旧版本的标记，别让旧版再重复 hook
  if (vm.__mtc_v13hooked) return true;
  vm.$watch('gpumemload', ...);
  vm.__mtc_v13hooked = true;     // ← 自己的守卫，独立命名
}
```

另外 `findVmOnce` 要**允许重新查找** —— Vue 实例销毁重建后缓存的 vm 就失效了：

```js
if (vmCache && vmCache.$data && !vmCache._isDestroyed
    && vmCache.$el && document.contains(vmCache.$el)) return vmCache;
vmCache = null;   // 失效就重新找
```

## 11. 写 JSON 字符串字段后**必须** `json.load()` 验证

**症状**：热调通道推送后**没有任何反应**，也不报错。

**原因**：在 JSON 的说明字段里写了裸双引号（`customClass = "AeeAndCui img_back"`），
直接把 JSON 结构破坏了。而热通道那边的 `JSON.parse` 失败是**静默跳过**的：

```js
try { JSON.parse(t); } catch (e) { return; }   // ← 不写 ack、不报错、什么都不做
```

**正确做法**：写完 JSON 一定要验一次：

```python
import json
json.load(open('tune.json', encoding='utf-8'))   # 抛异常就是坏了
```

**另外一个推论**：凡是"推送了但没反应"的情况，**先验 JSON，再怀疑别的**。

## 12. ★ 诊断脚本里塞写操作 = 违约

**症状**：本来只是想"看一眼"，结果把界面搞崩了。

**原因**：一个诊断脚本把「探测」和「修复试探」写在一起 —— 修复逻辑本身有
bug（对 `rotate(90deg)` 下的边界计算用了错误的轴），把 `BODY` 的 `overflow`
改成了 `visible` ⇒ **视口出滚动条 + 绝对定位基准变化 ⇒ 所有组件漂移**，
而且 renderer 当场卡死，连回滚脚本都注入不进去。

**正确做法**：

- **诊断永远纯读**：只 dump 数据、只测量、不写任何东西
- **写操作单独一轮、单独确认**
- 一次只改一个变量，改完立刻验证

**以及一条补充**：**renderer 一旦 hang，任何注入类的补救都是空的** ——
`executeJavaScript` 永不 resolve，什么都进不去。**直接重启软件**才是唯一解
（好在所有改动都在内存里，重启即净）。

## 13. 数据会变长的元素：定位要固定「变化的那一侧」

**症状**：对齐做好的两块，用着用着就错位了 —— 数字越长偏得越多。

**原因**：一块是 `left` 固定（左边缘对齐），一块是 `right` 固定（右边缘对齐）。
`left` 固定的那块，数字变长时内容**向右长** ⇒ 它的**右边缘**（也就是用来对齐别人的那一侧）
一直在飘。

**正确做法**：**看哪一侧需要对齐，就固定哪一侧**：

- 右边缘要对齐别人 → 固定 `right`，让它只往左长
- 左边缘要对齐 → 固定 `left`

本项目就是这么解决的（`left:auto; right:-11px`），改完对齐与数据长度**永久无关**。

## 14. `width: auto` 优于「加宽到某个固定值」

**症状**：皮肤写死了 `width:134px`，内容一长就被 `flex-shrink` 压扁、文字被裁。

**原因**：块是 flex 容器，宽度固定且内容溢出时，子元素会被压缩。

**正确做法**：

```css
.target{ width:auto !important; min-width:0 !important; }
.target *{ white-space:nowrap !important; flex-shrink:0 !important; }
```

**`width:auto` + `flex-shrink:0`** 是治「皮肤写死尺寸把内容挤掉」的通用拳 ——
换字号、换内容长度都不用重新算数值。

## 15. 改完不知道生效没有？先看这几个信号

排查顺序（从便宜到贵）：

1. **热通道回执文件**的**时间戳** —— 有没有推送成功
2. **产物里有没有该功能留下的专属字段** —— 比看文件修改时间可靠得多
3. `document.querySelectorAll('你的选择器').length` —— 元素在不在
4. 最终**只能靠人眼**看副屏（USB 直驱屏是抓不到屏的：`GetSystemMetrics(80)=1`，
   它不算 Windows 显示器）

> 本项目注入器会 `webContents.capturePage()` 自拍一张图落盘 —— 这是**唯一的**看图方式。
