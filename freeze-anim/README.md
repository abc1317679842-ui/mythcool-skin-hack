# freeze-anim —— 副屏「闪黑」诊断工具（**独立于注入器**）

> ⚠️ **这不是注入器的功能**，也不属于皮肤改造工作流。
> 它是 [docs/05-闪黑排查.md](../docs/05-闪黑排查.md) §4.5 那个 **A/B 测试**的工具化版本：
> 把**当前皮肤**的全部 CSS 动画/过渡停掉，用来判断「闪黑是不是页面动画引起的」。
>
> 仓库默认**不做**任何动画冻结。要不要把它并进你自己的皮肤配置（`tune.json` 的 `css` 字段）
> 是**你自己**的选择，见 docs/05 §4.7。

---

## 它做什么

往皮肤页面注入一张样式表（`id=__mtc_freeze`）：

```css
*{animation:none !important;}*{transition:none !important;}
```

- **只动 DOM/CSS 层**：元素不删、仍在合成树里，只是不再动
- **推流不受影响**：帧率、每帧字节数、USB 带宽、编码负载全部不变
  —— 只是「画面内容不再变化」，所以它不会用「把推流掐掉」的方式掩盖现象
- **只对目标皮肤生效**：页面内每 2.5 秒自检，切到别的皮肤自动摘掉样式表，切回来自动补上
- **页面重建自愈**：皮肤切换会销毁并重建渲染进程，主进程守卫会在 10 秒内重新冻结
- **完全可逆**：`undo` 一条命令恢复原样；Myth.Cool 重启后本次冻结自动失效

## 怎么用

需要用**管理员终端**（Myth.Cool 主进程通常是提权的，非提权 attach 会失败）：

```powershell
# 冻结（幂等，可重复跑）
& '<你机器上带 frida 的 python.exe>' freeze_anim.py

# 只查状态，不改任何东西
… freeze_anim.py status

# 解除
… freeze_anim.py undo
```

> 用你机器上**装了 frida 的 python** 跑 —— 注入器自带的
> `venv\Scripts\python.exe` / `python\python.exe` 一般就装了 frida。
> 也可以显式指定 pid：`freeze_anim.py apply <pid>`。

## 判读结果

| 现象 | 结论 |
|---|---|
| 冻结后闪黑**消失** | 触发源在**页面渲染/合成**侧（该皮肤的持续动画）→ 可按 docs/05 §4.7 处置 |
| 冻结后闪黑**照旧** | 与页面动画无关 → 问题在抓帧之后的 **USB/驱动/屏/供电**，页面侧怎么改都没用 |

**注意**：冻结期间 **GIF 图片仍会动**（GIF 是图片帧动画，不是 CSS 动画）、
**轮播仍会跳页**（那是 JS 改 inline transform）、**数据数字仍会刷新**（JS 更新）。
这三样是刻意的 —— 它们给了测试「前后一致」的对照组：如果它们还在动而闪黑消失了，
就说明问题出在「持续动画」这一类，而不是「任何画面变化」。

## 已知坑（别再踩）

- **pid 一定要选对**：本工具优先从 `C:\ProgramData\MythCoolInject\log\inject.log` 里读
  最近的 `main-pid`。**不要用「父进程不在 MythCool 集合里」这种启发式** ——
  实测在有启动器进程的机器上会选到启动器/GPU 进程，attach 失败事小，
  **扰到渲染管线会把副屏整屏定格**（详见 docs/04 的 #20 / #21）。
- 冻结是**运行时**的：Myth.Cool 重启（换 pid）后需要重新跑一次；
  想长期生效就把 CSS 固化进 `tune.json`（docs/05 §4.7 做法 B）。
